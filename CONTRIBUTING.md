# Contributing to throughline

Thanks for helping. This repo is a Claude Code plugin marketplace with one plugin, `pipeline`
(`plugins/pipeline/`). Bug reports, ideas and pull requests are all welcome; for anything large,
open an issue first so we can agree on the shape before you build it.

## Commit messages and PR titles: Conventional Commits

Releases, version numbers and [CHANGELOG.md](CHANGELOG.md) are generated by
[release-please](https://github.com/googleapis/release-please) from the commit messages on `main`.
Pull requests are **squash-merged**, and the PR title becomes that commit message, so the PR title
must follow [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>[(scope)][!]: <subject starting with a lowercase letter>
```

The `pr-title` check enforces it. Types, and whether they appear in the release notes:

| Type | Use for | In release notes | Version bump (below 1.0) |
| --- | --- | --- | --- |
| `feat` | a new capability | Features | minor |
| `fix` | a bug fix | Bug Fixes | patch |
| `perf` | a speed-up | Performance | patch |
| `deps` | a dependency change users notice | Dependencies | patch |
| `revert` | reverting an earlier commit | Reverts | patch |
| `docs`, `refactor`, `test`, `build`, `ci`, `chore`, `style` | everything else | hidden | none |

A breaking change is marked with `!` after the type (`feat!: ...`) or a `BREAKING CHANGE:` footer.
While the version is below 1.0 it bumps the minor version.

Examples: `feat(runner): resume a stopped run`, `fix(spec-check): accept v4 headings`,
`docs: explain pipeline.json budgets`.

## Development setup

You need:

- Python **3.12 or newer** (the scripts use 3.12 f-string syntax). No third-party packages.
- `git`, `go` and Node (`npx`) on `PATH`: many tests drive them in scratch repos.
- Optionally [ruff](https://docs.astral.sh/ruff/) and the
  [Claude Code CLI](https://docs.claude.com/en/docs/claude-code) for the lint and validate checks.

Run everything CI runs, from the repo root:

```bash
python3 plugins/pipeline/tests/run.py
```

That runs the suite spread over one worker process per CPU (`-j N` to change it, `-v` for every
shard's output). Plain `python3 -m unittest discover -s plugins/pipeline/tests` still works, one
test at a time; use it, or `python3 -m unittest test_pipeline.NextTest` from `plugins/pipeline/tests`,
for a single module or class. No test may use `setUpClass` or `setUpModule`: the runner puts tests
of one class in different processes.

```bash
ruff check .
```

```bash
claude plugin validate .
```

To try your working copy in Claude Code, add it as a local marketplace:

```
/plugin marketplace add /path/to/throughline
/plugin install pipeline@throughline
```

### Tests that skip

Tests skip themselves when what they check is not there:

- **Without `heph` on `PATH` (5):** `test_runner_status.DetachedTest` starts the real runner against
  the fixture repo, whose `required_tools` include `heph` (content_buddy's build tool). CI does not
  install it, so CI reports 5 skips; with `heph` installed you get none.
- Tests that need `go` (`test_diff_coverage`, `test_mutation_sample`) skip without it. CI installs
  Go, so they run there.

## Lint

`ruff.toml` enables only bug-finding rules (pyflakes and pycodestyle's `E4`/`E7`/`E9`), tuned to
the current code. No formatter is enforced; please match the surrounding style rather than
reformatting files you are not otherwise changing.

## Documentation

The documentation site is `mkdocs.yml` plus `docs/`, built by [Zensical](https://zensical.org)
and published to GitHub Pages from `main` by `.github/workflows/docs.yml`. It needs
[`uv`](https://docs.astral.sh/uv/):

```
make docs         # docs/check.py, then the strict build to out/site
make docs-serve   # preview at http://127.0.0.1:8000
```

`docs/check.py` fails when a command, agent, skill or `pipeline.json` key in the plugin has no entry
on its reference page, or a page is missing from the nav. The `docs` check runs `make docs` on every
PR. How a page is written: `docs/guides/develop/docs.md` and `.claude/rules/docs-voice.md`; with
Claude Code, `/docs` and `/docs-audit` apply them.

## Releases

Maintainers only: merge the open `chore(main): release x.y.z` PR that release-please maintains.
It bumps `version.txt` and the `version` in `plugins/pipeline/.claude-plugin/plugin.json`, updates
`CHANGELOG.md`, tags `v<version>` and creates the GitHub release. Do not edit those versions by
hand; the `manifests` check fails if `plugin.json` and `version.txt` disagree.
