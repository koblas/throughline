# {{name}} feature specs

One file per feature, `docs/specs/<slug>.md`, written by `/pipeline:intent-and-goal` once its
scenarios are approved: the feature's goal, its scenario tables, and one sub-issue per scenario.
The rules a feature changes live in `docs/product/` (the spec links them, it does not restate
them). A feature's retro is `docs/specs/<slug>.retro.md`, beside its spec.
